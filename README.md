# sendinggmail 批次 Gmail 寄信工具

一個批次寄送 Gmail 郵件的小工具。使用者將 Excel 檔案匯入軟體後，軟體會自動寄信給檔案中列出的每一個收件人信箱，可選擇是否客製化內容、收件人類型（收件人／副本／密件副本），以及寄送時間。

## 專案結構

```
sendinggmail/
├── app.py                  # Streamlit 網頁介面（畫面、使用者互動）
├── mailer.py                # 寄信核心邏輯（樣板置換、去重、批次分組、SMTP 寄送）
├── requirements.txt          # Python 套件清單
├── .streamlit/config.toml    # 介面主題、工具列設定
├── sample_recipients.xlsx    # 測試用範例收件人名單（假資料）
└── README.md
```

這個專案是**單一支 Python 程式**，沒有前後端分離——`app.py` 負責畫面跟使用者互動，`mailer.py` 負責實際寄信邏輯，兩者在同一個 Streamlit process 裡執行，不需要另外啟動 API 伺服器。

## 技術

| 項目 | 使用技術 |
|---|---|
| 介面 | Streamlit（本機執行的網頁介面，純 Python 寫成，不用另外寫 HTML/CSS/JS） |
| 讀取 Excel | pandas + openpyxl |
| 寄信方式 | Python 內建 `smtplib`，透過 Gmail SMTP 伺服器 + 應用程式密碼寄信 |
| 排程 | Python `threading`（背景執行緒等到指定時間再寄） |

不需要 Google Cloud Console、不需要 OAuth 設定、不需要資料庫，全部運算都在你自己電腦上執行。

## 功能區塊

| 區塊 | 說明 |
|---|---|
| 1. 上傳 Excel | 上傳收件人名單，欄位用 A、B、C 字母對照原始 Excel 順序，選出哪一欄是信箱 |
| 2. 撰寫信件內容 | 填主旨/內文；可勾選「客製化寄信」，用 `{{欄位名稱}}` 依每筆資料個別產生內容 |
| 3. 收件人類型與寄送批次 | 選「收件人（一般）」／「副本（CC）」／「密件副本（BCC）」，設定一次寄送人數 |
| 4. 寄送時間 | 選「立即寄送」或「排程寄送」（指定未來日期時間） |
| 5. 確認並寄送 | 顯示有效收件人數、重複信箱去重提示，按下寄送後顯示進度與結果 |

## 啟動

以下指令都在專案資料夾內執行（`cd` 進 `sendinggmail` 之後）：

```bash
# 1. 建立虛擬環境（只需要做一次）
python3 -m venv .venv

# 2. 啟用虛擬環境（每次開新的終端機視窗都要重做這步）
source .venv/bin/activate

# 3. 安裝套件（只需要做一次，之後 requirements.txt 有更新才需要重跑）
pip install -r requirements.txt

# 4. 啟動軟體
streamlit run app.py
```

執行完第 4 步後，終端機會顯示一個網址（預設 `http://localhost:8501`），並自動幫你開啟瀏覽器；
如果沒有自動開啟，手動複製那個網址貼到瀏覽器打開即可。看到終端機持續顯示執行中（沒有跳出錯誤訊息）即成功。

> 之後每次要使用軟體，只需要重做「2. 啟用虛擬環境」跟「4. 啟動軟體」這兩步就好，
> 不用每次都重新建立虛擬環境或重新安裝套件。

## 第一次使用前：申請 Gmail 應用程式密碼

軟體是透過 Gmail 的 SMTP 伺服器幫你寄信，**每一個要用這個軟體寄信的人，都要用自己的 Google 帳號申請一組專屬的應用程式密碼**（不能共用別人的）。全程在 Google 帳號設定頁面點滑鼠完成，大概 2 分鐘，不需要下載任何檔案。

### 1. 開啟兩步驟驗證（如果還沒開）

應用程式密碼必須先開啟「兩步驟驗證」才能申請。

1. 打開 [myaccount.google.com/security](https://myaccount.google.com/security)
2. 找到「兩步驟驗證」，如果顯示「已開啟」就跳到下一步；沒開的話點進去，跟著畫面指示（通常是綁定手機號碼收驗證碼）完成開啟

### 2. 產生應用程式密碼

1. 打開 [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords)
2. 可能要再輸入一次密碼確認身份
3. 「應用程式名稱」隨便打，例如 `批次寄信工具`，按「建立」
4. 畫面會顯示一組 **16 碼的密碼**（例如 `abcd efgh ijkl mnop`），把它複製下來
   - 這組密碼只會顯示這一次，關掉視窗就看不到了，如果沒存到就要回頭重新申請一組
   - 這組密碼**絕對不要分享給別人**，效果等同於能用你的帳號寄信

> 如果 `myaccount.google.com/apppasswords` 打開後找不到「應用程式密碼」的選項，通常代表帳號的兩步驟驗證還沒開（回到步驟 1），或者是學校 / 公司帳號被管理員關閉了這個功能——遇到後者，改用個人 Gmail 帳號重新申請即可，不影響其他步驟。

## 操作手冊

啟動軟體（`streamlit run app.py`）、瀏覽器打開網頁後，依序操作：

1. **登入 Gmail 帳號**：網頁一開始會在畫面中間顯示登入框，輸入「寄件者顯示姓名」（收件人會看到的
   寄件人名稱，不填就只會顯示你的 email 地址）、Gmail 信箱與應用程式密碼，按「登入」。
   登入成功後上方會顯示已登入的信箱；因為密碼不會被儲存，**每次重新啟動軟體都要重新輸入一次**。
2. **上傳 Excel 名單**：在「1. 上傳 Excel 收件人名單」上傳你的 `.xlsx` / `.xls` 檔案，
   畫面會預覽前 20 筆資料，接著從下拉選單選出「哪一欄是收件人信箱」。
   - 副檔名限定 `.xlsx` / `.xls`，只讀第一個工作表，第一列一定要是欄位標題
3. **撰寫信件內容**：在「2. 撰寫信件內容」填「主旨」跟「內文」。
   - 如果想要每封信內容依 Excel 資料不同（例如帶入姓名），勾選「客製化寄信」，
     畫面會直接列出可複製的變數標籤（例如 `{{姓名}}`），貼到主旨/內文即可，系統會針對每個人分別寄一封信。
   - 不勾選的話，所有人收到的內容都一樣。
   - 客製化模式下每封信一律直接寄給本人（收件人類型欄位會鎖住），因為每封信本來就只給一個人，
     不需要再用副本/密件副本繞一圈。
4. **設定收件人類型與批次**：在「3. 收件人類型與寄送批次」選擇這批信要用
   「收件人（一般）」、「副本（CC）」還是「密件副本（BCC）」，並設定一次寄送人數
   （例如設 20，代表每封信會一次放 20 位收件人）。
   - 密件副本模式下，「收件人」欄位會顯示標準的「不公開的收件者」佔位符，不會洩漏你自己或任何人的信箱。
   - 分組順序固定依照 Excel 由上到下的列順序切分（例如 20 人一組、共 45 筆，就是
     第 1 到 20 列、第 21 到 40 列、第 41 到 45 列分三批寄，不會跳著選）；同一個信箱如果在
     Excel 裡重複出現多列，系統會自動去重，只處理第一次出現的那一列，避免同一人收到多封。
5. **設定寄送時間**：在「4. 寄送時間」選「立即寄送」或「排程寄送」，
   排程寄送要選未來的日期與時間。
6. **確認並寄送**：在「5. 確認並寄送」確認有效收件人數沒問題後，按下「寄送」。
   - 立即寄送：畫面會即時顯示進度條，完成後顯示成功/失敗人數。按鈕在處理中會鎖住，避免重複點擊造成重複寄送。
   - 排程寄送：畫面顯示「已排程於 ×××× 自動寄送」，**必須讓執行 `streamlit run app.py`
     的終端機視窗持續開著**（不能關閉、不能讓電腦睡眠），時間到才會真正寄出。

## 環境需求

- Python 3.9 以上
- Gmail 帳號（需開啟兩步驟驗證 + 應用程式密碼）

## 部署

這是設計給**本機執行**的個人工具，不是給多人同時上線使用的網站，所以沒有部署到雲端伺服器的規劃——每個使用者在自己電腦上 `streamlit run app.py` 啟動即可，帳號密碼也只存在自己電腦的當次執行階段，不會經過任何第三方伺服器。

## 專案開發歷程

**第一階段：需求釐清與技術選型**
確認核心需求（Excel 匯入、客製化寄信、收件人類型、批次與排程），並在 Gmail API OAuth 與 SMTP 應用程式密碼之間選擇技術方案。

**第二階段：Gmail 授權方式的調整**
最初採用 Gmail API + OAuth，但實際申請時發現學校 Google Workspace 帳號的兩步驟驗證、OAuth 應用程式設定會被管理員限制，設定流程對非技術使用者也太複雜。後來改用「Gmail SMTP + 應用程式密碼」，設定步驟從申請 Google Cloud 專案簡化成兩步驟驗證 + 產生一組密碼，大幅降低使用門檻。

**第三階段：介面設計**
參考 Notion / Linear 一類簡約產品的視覺風格，把介面改成卡片式分區、置中版面、統一配色，並拿掉不必要的 emoji 與 Streamlit 預設工具列。

**第四階段：實際測試與除錯**
透過反覆的真實寄信測試，抓出並修正了幾個關鍵問題：
- 客製化寄信搭配副本/密件副本時，誤把每封個人化的信都繞回寄件人自己
- Excel 欄位標題是純數字（例如「7」）時，變數比對失敗
- Excel 名單裡有重複列，導致同一人收到多封
- 密件副本模式把寄件人自己的信箱洩漏在「收件人」欄位
- 加上寄送按鈕的防重複送出鎖

## 軟體運作邏輯與角色

**資料流程：**

```
使用者上傳 Excel、填寫主旨/內文、設定收件人類型
        ↓
Streamlit（app.py）讀取畫面輸入、驗證資料
        ↓
呼叫 mailer.py 的 send_campaign()
        ↓
依樣板置換客製化內容、依批次大小分組、組成郵件
        ↓
smtplib 透過 Gmail SMTP 伺服器實際寄出
        ↓
畫面顯示「寄送完成：成功 X 人、失敗 X 人」
```

**各軟體 / 套件的角色：**

| 軟體 / 套件 | 角色 |
|---|---|
| Streamlit | 讓 Python 程式直接變成可操作的網頁介面，不用另外寫前端 HTML/CSS/JS |
| pandas / openpyxl | 讀取使用者上傳的 Excel 檔案，轉成程式可以處理的資料 |
| smtplib（Python 內建）| 透過 Gmail 的 SMTP 伺服器，實際把郵件送出去 |
| Gmail 應用程式密碼 | 讓程式能夠用你的帳號登入寄信，不需要把真正的登入密碼交給程式 |
| Git / GitHub | 版本控管與備份，記錄每一次修改 |
| 終端機 | 執行 `streamlit run app.py` 啟動程式、安裝套件的地方 |
| Claude（AI）| 協助撰寫程式碼、除錯、調整介面設計 |
